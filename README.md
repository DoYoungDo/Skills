# Skills

本仓库收集用于 AI 编程助手的技能（Skills），覆盖需求澄清、架构设计、开发执行、代码分析、提交规范和沟通方式。每个 skill 以独立目录组织，`SKILL.md` 定义其用途、触发条件、工作流程和约束，部分目录还包含参考文档或辅助脚本。

## Skill 一览

当前仓库包含以下 8 个 skill：

| Skill | 主要作用 | 适用场景 |
| --- | --- | --- |
| [agent-task-workflow](agent-task-workflow/SKILL.md) | 规范 AI agent 的任务执行流程，包括需求对齐、任务拆分、测试驱动开发（TDD）、结果验证、checkpoint 提交、失败恢复和交付汇报。 | 新功能开发、缺陷修复、重构及需要持续验证的多步骤工程任务；文档和只读任务可采用轻量流程。 |
| [architecture-designer](architecture-designer/SKILL.md) | 辅助系统架构设计与评审，分析架构模式、技术选型、非功能需求和方案取舍，并通过架构决策记录（ADR）记录关键决策。 | 新系统设计、现有架构评审、数据库选型、可扩展性规划和架构决策文档编写。 |
| [code-commit](code-commit/SKILL.md) | 根据 Git 改动生成中文 Conventional Commits 提交信息；在用户明确授权后，检查提交范围和敏感信息，执行暂存、提交及提交后验证。 | 编写提交信息，或在明确授权后完成 Git 提交。 |
| [dev-expert](dev-expert-1.21.7/SKILL.md) | 提供面向 Java、PHP/CMS、前端和 MySQL 的全栈开发指导，涵盖 API 设计、代码生成与审查、Bug 诊断、重构、测试、性能优化、技术选型及工程治理，并按任务路由到子技能。 | 综合开发任务、复杂问题排查、Spec 驱动开发、项目知识管理，以及生产就绪、安全与交付质量评估。 |
| [go-code-analysis](go-code-analysis/SKILL.md) | 规范 Go 代码分析的工具选择，优先通过 gopls MCP 获取工作区、符号、引用、API 和诊断等语义信息，再按需补充源码阅读与测试。 | 理解 Go 代码结构、追踪调用与引用、评审代码、检查编译和类型问题，以及分析重构影响。 |
| [i-have-adhd](i-have-adhd/SKILL.md) | 调整回答方式以降低 ADHD 读者的阅读和执行负担：优先给出下一步行动、对多步骤任务编号、重述进度、减少旁支信息，并明确时间预估与已完成成果。 | 用户希望获得更易执行、注意力负担更低的回答；通过 `/i-have-adhd` 显式启用，持续到用户要求退出。 |
| [karpathy-guidelines](karpathy-guidelines/SKILL.md) | 通过先思考再编码、优先简单方案、保持最小修改范围和定义可验证目标，减少 AI 编程中的过度设计、隐含假设与无关改动。 | 编写、审查或重构代码时约束实现范围，提升修改的可理解性与可验证性。 |
| [requirement-analysis](requirement-analysis/SKILL.md) | 通过逐轮结构化提问澄清背景、目标、用户、场景、功能边界、约束与验收标准，最终整理成可直接交给 AI 实现的独立需求文档。 | 需求模糊、关键条件缺失，或用户明确要求分析与梳理需求；需求已明确时无需启动澄清流程。 |

## 使用方式

1. 根据任务从上表选择合适的 skill，阅读对应的 `SKILL.md`。
2. 按所使用 AI 助手的技能加载机制安装或加载该 skill。若目录包含参考文档、脚本等资源，应保留完整目录结构。
3. 在对话中明确任务目标，必要时指定 skill 名称；具体触发方式、工具依赖和执行边界以对应 `SKILL.md` 及宿主支持情况为准。

`dev-expert` 的目录名为 `dev-expert-1.21.7`，其技能名称为 `dev-expert`。`go-code-analysis` 优先依赖可用的 gopls MCP 工具；工具不可用时，其定义允许使用补充工具，并要求说明分析限制。

## 维护说明

新增或调整 skill 时，请同步更新上表中的作用、适用场景和链接。各 skill 的详细规则以自身的 `SKILL.md` 为准。
